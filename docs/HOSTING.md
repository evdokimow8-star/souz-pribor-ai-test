# Публичная демонстрация

Адрес: https://ai-kabinet.ru/pribor-studio/

Python-приложение работает отдельной systemd-службой на сервере владельца. Код не встраивается в приложение Радара. Сервис слушает `127.0.0.1:18769`; Caddy направляет к нему только путь `/pribor-studio/`, снимая префикс. Все ссылки интерфейса поддерживают запуск в подпапке.

Шаблоны: `deploy/souz-pribor-demo.service`, `deploy/Caddyfile.fragment`. Ключ задаётся только в защищённом серверном EnvironmentFile; файл ключа и рабочее состояние не входят в Git.

На сервере применяется существующий шлюз владельца к OpenRouter: `LLM_BASE_URL` и серверный `LLM_GATEWAY_TOKEN`. Поддерживается тот же контракт API и те же ценовые ограничения. Токен шлюза отправляется только на его точный разрешённый адрес; при прямом подключении к OpenRouter этот токен не передаётся. Отдельный сервер или платный сервис для демонстрации не создаётся.

Публичный режим включается явно через `--public-origin` вместе с `--budget-file`. Обычный запуск `python -m pribor` остаётся локальным.

## Расходы

Общий согласованный бюджет задания — **$0.50**. В начальный расход включены **$0.017678**, уже потраченные при подготовке примеров. Новые ответы учитываются по стоимости, сообщённой OpenRouter, с округлением вверх до микродоллара.

Перед вызовом атомарно резервируется $0.10. В API передаётся потолок $1 за миллион входных токенов. Для Gemini 3.8 Flash потолок выхода составляет $3.75 за миллион, для Gemini 3 Flash Preview — $3. Вход и максимальный ответ ограничены. Если стоимость ответа неизвестна, резерв сохраняется при перезапуске службы. Оплаченный ответ учитывается даже после отклонения валидатором.

Бюджет не сбрасывается перезапуском и не изменяется новыми параметрами запуска. Для посетителя действует 3 генерации за 15 минут. IP хранится только как HMAC с отдельной случайной солью. Готовые примеры и выгрузки не вызывают модель.

При недостаточном остатке новый запрос блокируется; сохранённые примеры продолжают работать. Это ограниченная демонстрация для проверки задания, не неограниченный публичный сервис.

## Выпуск

Исходники фиксируются отдельным коммитом и проходят локальные тесты и браузерную проверку. На сервер передаётся архив именно этого коммита с SHA-256, распаковывается в отдельный неизменяемый release-каталог. Отдельная служба запускается через `current`. Перед изменением маршрута проверяется исходный хэш Caddyfile, сохраняется резервная копия и проверяется новая конфигурация. Остальные маршруты сохраняются побайтово; Caddy выполняет reload.

После выпуска проверяются публичный HTTPS, статические файлы, оба примера, конфигурация и состояние прежних служб. Тесты и сборки на сервере не запускаются. API-ключи, SSH-доступ и операторские файлы в репозиторий не включаются.
